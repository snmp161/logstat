# ТЗ: `logstat` — демон подсчёта кодовых слов в логе → Redis

> Финальная версия. Язык реализации — **Go**. Конфигурация — **YAML-файл**.
> Документ самодостаточен и предназначен для передачи в разработку (в т.ч. Claude Code).

---

## 1. Назначение

Демон непрерывно читает пишущийся текстовый лог-файл (nginx, приложение — **любое ПО, пишущее построчно**), ищет в каждой строке заданные кодовые слова подстрокой и ведёт в Redis инкрементные счётчики по каждому слову. Счётчик растёт со временем и обнуляется по расписанию (по умолчанию раз в сутки в полночь). Внешний считыватель на другой стороне снимает значение по этому циклу. Самосброс отключаем.

Демон не привязан ни к nginx, ни к конкретному формату лога: он работает с сырыми строками и матчит подстроку.

---

## 2. Функциональные требования

1. Следить за одним лог-файлом в режиме «tail -F»: читать только новые строки по мере записи.
2. Для каждой новой строки проверять вхождение каждого кодового слова из списка в конфиге.
3. Матчинг — **подстрока в любом месте строки**, регистрозависимо. Счёт **по строке, не по вхождению**: слово встретилось в строке дважды → +1. Два разных слова в одной строке → инкрементится каждое.
4. Инкременты копить в памяти и сбрасывать в Redis пачкой раз в `flush_interval` секунд (не на каждую строку).
5. При сбросе пачки: `INCRBY` целочисленного счётчика, затем — если включён `heartbeat_key` — `SET` форматированного heartbeat-значения с новым итогом.
6. Самосброс счётчиков в 0 по расписанию — **опционально** (см. §6).
7. Прозрачно проходить ротацию лога (файл ротируется, напр., раз в час по объёму) без потери потока и без повторного пересчёта.
8. Вся конфигурация — из YAML-файла (см. §8).

---

## 3. Правило матчинга

Кодовые слова по умолчанию: `get-number`, `get-sms`, `getNumber`, `getStatus`.

Для строки `line` и каждого слова `w` из списка: если `line` содержит `w` как подстроку — счётчик `w` += 1. Все слова проверяются независимо, регистрозависимо.

> ⚠️ **Префиксные пересечения.** При подстрочном матчинге `getStatus` совпадёт и внутри гипотетического `getStatusExtended`. Среди текущих четырёх слов пересечений нет (ни одно не является подстрокой другого). При добавлении новых слов в конфиг это надо проверять. Отразить в README и выдавать предупреждение при валидации конфига (§8).

---

## 4. Работа с лог-файлом и ротацией

- Старт: позиционироваться в **конец** файла (аналог `tail -n0`) — старьё не считать.
- Читать всё дописываемое, включая переход через ротацию.
- Поддержать оба режима logrotate:
  - `create` — rename старого + новый файл (смена inode);
  - `copytruncate` — файл усечён на месте (размер поехал назад).
- При исчезновении / пересоздании файла — дождаться нового и продолжить с его начала.
- **Демон обязан нормально стартовать, когда лог-файла ещё нет** (ПО-источник может подняться позже): не падать, ждать появления файла, затем начать чтение.
- Реализация: `github.com/nxadm/tail` c `ReOpen: true`, `Follow: true`, `Location` в конец, `Poll` — опционально из конфига (для сетевых ФС, где inotify не работает).

## 5. Схема ключей Redis

`<host>` = короткое имя хоста (`hostname -s`), `<action>` = кодовое слово.

| Назначение | Ключ | Значение | Операция | Условие |
|---|---|---|---|---|
| Служебный счётчик | `logstat:counter:<host>:<action>` | целое число | `INCRBY` / `SET 0` | всегда |
| Значение для мониторинга (heartbeat) | `logstat:heartbeat:<host>:<action>` | `server=<host> time=<iso8601> type=<action> lines=<N>` | `SET` | `heartbeat_key: true` |

Два ключа: атомарно инкрементить форматированную строку нельзя, поэтому счёт ведём на целочисленном ключе, а `<N>` для форматированного значения берём из ответа `INCRBY`. Время — ISO-8601 с таймзоной (совместимо с `date -Iseconds`).

**Heartbeat-ключ отключаемый.** Параметр конфига `heartbeat_key` (bool, дефолт `true`) целиком управляет вторым ключом. При `heartbeat_key: false` демон ведёт только целочисленные счётчики: heartbeat не создаётся при инициализации, не пишется при флаше и не трогается при сбросе (в т.ч. при `logstat clear`) — это режим для считывателей, которым достаточно `INCRBY`-счётчика. Уже существующий heartbeat-ключ при выключении параметра **не удаляется**: остановить обновления — задача софта, подчистить ключ — оператора.

> ⚠️ **Потенциальная коллизия ключей — на внимание оператора.** Ключи содержат только `<host>` и `<action>`. Коллизия возможна ровно в одном сценарии: несколько инстансов на одном хосте, у которых в конфиге **один и тот же** Redis (host/port/db) **и** пересекающиеся `actions` — тогда они пишут в общий ключ и затирают друг друга. Обычно этого не бывает: у разных конфигов, как правило, и Redis разный (свой host/db в каждом), а если Redis один — достаточно непересекающихся наборов `actions`. Софт этот случай **не предотвращает** (ответственность оператора) — просто держи в голове при настройке нескольких инстансов на общий Redis. Отразить предупреждением в README.

## 6. Самосброс счётчиков (отключаемый)

Управляется двумя независимыми параметрами конфига:

- `reset.enabled` (bool, дефолт `true`) — включает/выключает самосброс целиком.
- `reset.schedule` (строка, cron-выражение, дефолт `"0 0 * * *"`) — расписание обнуления в **стандартном 5-польном cron-синтаксисе** (`минута час день месяц день_недели`). Дефолт `"0 0 * * *"` = «раз в сутки в полночь». Часовой пояс — локальный для хоста.

Никакой самописной логики времени: расписание целиком определяется cron-выражением через библиотеку `github.com/robfig/cron/v3`. Это убирает неоднозначность «час игнорируем, значимы MM:SS» и даёт гибкость бесплатно: `1 * * * *` — 1-я минута каждого часа (прежний `:01:00`), `*/30 * * * *` — каждые полчаса, `0 0 * * *` — раз в сутки в полночь и т.п.

> Стандартный cron — 5 полей, срабатывание всегда в `:00` секунд целевой минуты. Для сброса раз в сутки/час этого достаточно. Секунды в стандартном cron не выражаются; если когда-нибудь понадобится секундная точность — `robfig/cron` умеет 6-польный режим (`cron.WithSeconds()`), но по умолчанию используем строгий стандартный 5-польный.

Логика при срабатывании: сначала флашится остаток буфера, затем по каждому слову `SET counter 0` + запись heartbeat-значения `lines=0` (если `heartbeat_key: true`).

При `reset.enabled=false` демон только считает; обнуление выполняет кто-то снаружи (внешний скрипт/таймер или ручной `logstat clear`). CLI-подкоманда `clear` доступна всегда, независимо от `reset.enabled` (§9).

**Граница интервала:** строки, лежащие в буфере на момент срабатывания расписания, попадают в финальный флаш **перед** обнулением — т.е. учитываются в завершающемся интервале, не в новом. Отдельной гонки нет: и подсчёт, и сброс идут в одном процессе.

## 7. Восстановление после сбоя

- Счётчик хранится в Redis, не в памяти демона → рестарт не теряет накопленное за час.
- После рестарта демон позиционируется в конец файла. Строки, записанные за время простоя, не считаются (счётчик продолжается с текущего значения). Персист файлового оффсета **сознательно не делаем** — ради простоты.
- Целочисленный счётчик инициализировать `SET ... 0` только если ключа ещё нет (`SET ... NX`); существующий не затирать.
- Стартовать корректно при отсутствующем лог-файле (§4) и при недоступном Redis (§10).

## 8. Конфигурация (YAML)

Путь к конфигу — флаг `--config /etc/logstat/config.yaml` (короткий `-c`). Значения по умолчанию встроены: при отсутствии поля берётся дефолт.

Пример `/etc/logstat/config.yaml`:

```yaml
# Путь к лог-файлу (любое ПО, пишущее построчно)
log_path: /var/log/app.log

# Кодовые слова для подсчёта (подстрочный матчинг, регистрозависимо).
# ВНИМАНИЕ: избегать слов, являющихся подстрокой другого слова из списка.
actions:
  - get-number
  - get-sms
  - getNumber
  - getStatus

# Период сброса накопленного буфера в Redis, секунды
flush_interval: 10

# Читать файл поллингом вместо inotify (для сетевых ФС). По умолчанию false.
poll: false

# Вести heartbeat-ключ logstat:heartbeat:<host>:<action> с форматированным
# значением для мониторинга. false — только целочисленные счётчики.
heartbeat_key: true

# Lock-файл этого инстанса (защита от повторного запуска).
# ВАЖНО: при нескольких конфигах на одном хосте путь должен быть РАЗНЫМ у каждого.
lock_file: /run/logstat/logstat.lock

redis:
  host: 127.0.0.1        # Redis может жить на другой машине
  port: 6379
  db: 0
  password: ""           # для requirepass; пусто — без AUTH

# Логирование самого демона
logging:
  level: info            # debug | info | warn | error
  output: journald       # journald (=stderr, подхватывает systemd) | file
  file: ""               # путь; используется только при output: file
                         # при нескольких конфигах путь должен быть РАЗНЫМ у каждого

# Самосброс счётчиков по cron-расписанию
reset:
  enabled: true          # false — демон только считает, обнуляет кто-то снаружи
  schedule: "0 0 * * *"  # стандартный 5-польный cron; дефолт — раз в сутки в полночь
```

Полный перечень параметров и дефолтов:

| Параметр | Тип | Дефолт | Назначение |
|---|---|---|---|
| `log_path` | string | `/var/log/app.log` | путь к лог-файлу |
| `actions` | list\<string\> | `[get-number, get-sms, getNumber, getStatus]` | кодовые слова |
| `flush_interval` | int (сек) | `10` | период сброса буфера в Redis |
| `poll` | bool | `false` | поллинг вместо inotify |
| `heartbeat_key` | bool | `true` | вести heartbeat-ключ для мониторинга |
| `lock_file` | string | `/run/logstat/logstat.lock` | lock-файл инстанса (уникальный на конфиг) |
| `redis.host` | string | `127.0.0.1` | хост Redis (может быть удалённым) |
| `redis.port` | int | `6379` | порт Redis |
| `redis.db` | int | `0` | номер БД Redis |
| `redis.password` | string | `""` | `AUTH`, если задан `requirepass` |
| `logging.level` | string | `info` | `debug`/`info`/`warn`/`error` |
| `logging.output` | string | `journald` | `journald` (stderr) или `file` |
| `logging.file` | string | `""` | путь лог-файла при `output: file` (уникальный на конфиг) |
| `reset.enabled` | bool | `true` | включить самосброс |
| `reset.schedule` | string | `"0 0 * * *"` | cron-расписание сброса (стандартный 5-польный) |

**Валидация при старте:** конфиг читается и парсится; `actions` непустой; предупреждение в лог, если какое-то слово — подстрока другого; `flush_interval > 0`; `reset.schedule` парсится как валидное cron-выражение; `lock_file` задан и его каталог создаваем; при `logging.output: file` поле `logging.file` непустое и путь записываем. При фатальной ошибке конфига — выход с ненулевым кодом (systemd покажет в статусе).

Библиотека парсинга: `gopkg.in/yaml.v3`.

## 9. CLI / режимы

- `logstat run --config <path>` — демон (основной режим).
- `logstat clear --config <path> [--action <w> | --all]` — ручной сброс счётчиков в 0 (ops/отладка). Работает всегда, независимо от `reset.enabled`.
- `logstat version` — версия/commit/дата сборки (вшиваются через ldflags, см. §13).
- `logstat --help` — справка.

Для трёх подкоманд достаточно стандартного пакета `flag` — без `cobra`, ради минимализма (можно пересмотреть, если CLI разрастётся).

## 10. Нефункциональные требования

- **Единственный экземпляр** — гарантируется systemd + `flock` на пути из `lock_file` (по умолчанию `/run/logstat/logstat.lock`) как страховка от ручного двойного запуска. При нескольких конфигах у каждого свой `lock_file`.
- **Грациозное завершение** — по `SIGTERM`/`SIGINT` (systemd stop) флашнуть остаток буфера и выйти с кодом 0.
- **Устойчивость к Redis** — Redis (возможно удалённый) недоступен → буфер копится в памяти, попытки повторяются, демон не падает и не теряет счёт; при восстановлении досбрасывает. `go-redis` держит реконнект сам.
- **Устойчивость к источнику лога и ротации** — рестарт ПО-источника и ротация лога не роняют демон; отсутствие файла на старте допустимо.
- **Ресурсы** — событийная модель (inotify), без busy-loop; минимальный CPU/RSS в простое.
- **Безопасность** — запуск под непривилегированным пользователем `logstat`; systemd-хардненинг (`NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`).
  - Группа для чтения лога зависит от владельца файла. Для nginx это обычно `adm`; для другого ПО — подогнать `SupplementaryGroups` под конкретный лог (иногда демону хватит обычных прав, если файл читаем всем). Отразить в README.

### 10.1 Логирование самого демона

Демон ведёт собственный лог о происходящем (старт/стоп, загруженный конфиг, факт и результат каждого флаша, срабатывание сброса, недоступность Redis и реконнект, ротация лог-файла, ошибки). Управляется блоком `logging` конфига:

- `logging.level` — `debug` / `info` (дефолт) / `warn` / `error`.
- `logging.output`:
  - `journald` (дефолт) — писать в **stderr**, откуда systemd складывает в journald (`journalctl -u logstat@<инстанс>`). Отдельной интеграции с journald-протоколом не требуется, достаточно stderr.
  - `file` — писать в файл, заданный `logging.file`. При нескольких конфигах путь у каждого свой. Ротацию этого файла обеспечивает внешний logrotate (демон только пишет; при `copytruncate`/rename переоткрытие своего лог-файла по сигналу `SIGHUP` — желательное поведение, отметить в README).
- Формат — человекочитаемый, с таймстампом и уровнем. Целевые/событийные записи не должны сыпаться на каждую строку лога (это шумно при высоком RPS) — по строкам только на `debug`.

## 12. Автотесты

**Юнит-тесты:**
- матчинг: подстрока, регистрозависимость, счёт по строке (двойное вхождение = +1), несколько слов в строке, префиксные пересечения (спец-кейс с предупреждением);
- парсер/валидатор конфига: дефолты, битый YAML, пустой `actions`, слово-подстрока, невалидный `reset.schedule`, пустой `logging.file` при `output: file`, незаданный `lock_file`;
- формирование ключей и форматной строки значения;
- парсинг ответа `INCRBY` и сборка `lines=<N>`;
- `heartbeat_key`: дефолт `true`, разбор `false`; при выключенном параметре heartbeat-ключ не создаётся ни при инициализации, ни при флаше, ни при сбросе, а уже существующий не затирается;
- парсинг и валидация `reset.schedule` как cron-выражения; расчёт времени следующего срабатывания (`cron.Schedule.Next`) для нескольких выражений (`1 * * * *`, `*/30 * * * *`, `0 0 * * *`).

**Интеграционные тесты:**
- Redis — через `github.com/alicebob/miniredis/v2` (без внешнего сервера в CI): `INCRBY`, `SET NX`, heartbeat-значение, сброс, режим `heartbeat_key: false`;
- tail + ротация — временный файл во временной директории: дописываем строки, эмулируем `create` (rename + новый файл) и `copytruncate` (truncate), проверяем корректность счёта и отсутствие двойного счёта;
- старт при отсутствующем файле: файл появляется позже — демон подхватывает;
- **сброс счётчиков (без ожидания реального расписания).** Тест не должен ждать наступления полуночи/минуты. Два уровня: (1) reset-функция вызывается напрямую и мгновенно проверяется обнуление счётчиков и запись `lines=0` в miniredis; (2) планировщик проверяется на расписании, срабатывающем в ближайшую секунду — либо cron в 6-польном режиме с секундами (`cron.WithSeconds()`, выражение вида «текущая секунда+1»), либо инъекция уже-наступающего момента, с таймаутом теста ~2–3 сек. Явно избегать боевого `reset.schedule`, который пришлось бы ждать минутами/часами;
- логирование: при `output: file` строки пишутся в указанный файл; уровень фильтрует (`debug`-события не сыпятся на `info`);
- graceful shutdown: посылаем сигнал, проверяем финальный флаш.

**Требования:** ключевая логика (матчинг, конфиг, reset, redis-слой) — покрытие ≥ 80%. `go test -race ./...` обязателен (гонки в связке горутин tail/flush/reset).

## 13. Сборка и упаковка

**Сборка:**
- `CGO_ENABLED=0 go build` со статической линковкой;
- версия/commit/date вшиваются через `-ldflags "-X main.version=... -X main.commit=... -X main.date=..."`;
- `Makefile` с целями `build`, `test`, `lint`, `package`, `clean`.

**Пакеты deb и rpm** — через `github.com/goreleaser/nfpm` (без fpm/ruby): один `nfpm.yaml` собирает оба формата из готового бинарника. Содержимое пакета:
- `/usr/bin/logstat` (бинарник);
- `/etc/logstat/default.yaml` — пример/дефолтный конфиг, как conffile / `%config(noreplace)` (не затирать правки при обновлении);
- `/lib/systemd/system/logstat@.service` (шаблонный юнит);
- postinstall: `useradd -r logstat`, `systemctl daemon-reload`;
- preremove (prerm): остановить все запущенные инстансы — `systemctl stop 'logstat@*.service'` (glob по stop работает для загруженных юнитов);
- postremove (postrm), **при удалении пакета**: снять осиротевшие enable-симлинки инстансов. Они созданы админом (`systemctl enable logstat@<имя>`), пакету не принадлежат и сами не удалятся — после исчезновения шаблона повиснут битыми ссылками. Пройтись по `.wants`-каталогам и удалить, затем `daemon-reload`:

  ```sh
  # postrm (remove): подчистить enable-симлинки инстансов шаблона logstat@
  for l in /etc/systemd/system/*.wants/logstat@*.service; do
      [ -L "$l" ] || continue          # нет совпадений — glob вернёт литерал, guard отсеет
      rm -f "$l"
  done
  systemctl daemon-reload 2>/dev/null || true
  ```

  Glob `*.wants` ловит инстансы в любом target (не только multi-user). nfpm поддерживает per-формат `scripts.preremove`/`scripts.postremove` — реализуемо и для deb, и для rpm одним набором.
- зависимости пакета минимальные (бинарник статический).

**Кросс-сборка:** `linux/amd64` и `linux/arm64`.

## 15. Деплой (systemd)

Юнит — **шаблонный** `logstat@.service`, чтобы одним юнитом обслуживать несколько логов: экземпляр `logstat@<имя>` читает конфиг `/etc/logstat/<имя>.yaml`. Так `logstat@app1` парсит `/etc/logstat/app1.yaml`, `logstat@nginx` — `/etc/logstat/nginx.yaml` и т.д. **Без завязки на Redis и на nginx**: Redis может быть на другой машине, буфер в памяти переживает его недоступность, а источник лога произволен.

```ini
[Unit]
Description=logstat (%i): count codewords in a log file -> Redis
# Никаких After=/Wants= на redis или nginx:
# Redis может быть на другой машине, а буфер в памяти переживает его недоступность;
# источник лога — произвольное ПО. Демон стартует независимо и сам переживает
# отсутствие Redis и отсутствие/ротацию лог-файла.
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/bin/logstat run --config /etc/logstat/%i.yaml
Restart=always
RestartSec=2
User=logstat
SupplementaryGroups=adm
# %i в RuntimeDirectory даёт свой /run/logstat/<инстанс> на каждый конфиг.
RuntimeDirectory=logstat/%i
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes

[Install]
WantedBy=multi-user.target
```

Запуск инстансов:

```bash
systemctl enable --now logstat@app1.service logstat@nginx.service
systemctl status 'logstat@*'
journalctl -u logstat@app1 -f
```

**Важно при нескольких инстансах на одном хосте:**
- у каждого конфига **свой** `lock_file` (напр. `/run/logstat/app1/logstat.lock`) — иначе второй инстанс не стартует из-за flock;
- при `logging.output: file` — **свой** `logging.file` у каждого;
- если инстансы смотрят в **один и тот же** Redis (host/port/db) — их наборы `actions` не должны пересекаться (иначе коллизия ключей, см. §5); разный Redis или разный `db` в конфигах снимают вопрос сами по себе.

При `reset.enabled=true` timer и clear-сервис не нужны. Раскатка — через Salt (`file.managed` для пакета и per-инстансных конфигов + `service.running` по списку инстансов) либо установка `.deb`/`.rpm` из GitHub Release. `SupplementaryGroups` подгоняется под владельца конкретного лога (§10).

Одиночный кейс (один лог) — просто один инстанс, напр. `logstat@default` с `/etc/logstat/default.yaml`.

## 17. Явно вне рамок (non-goals)

- Персист файлового оффсета между рестартами (строки за время простоя не досчитываются — осознанно).
- Несколько лог-файлов **одним процессом** (один демон = один лог; несколько логов = несколько инстансов шаблонного юнита `logstat@<имя>`, см. §15).
- Разбор формата лога по колонкам/полям — работаем с сырыми строками, матчинг подстрокой (сознательное решение).
- TLS до Redis, Redis Cluster, Sentinel (одиночный инстанс).

## Приложение A. Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Язык | Go, статический бинарник (`CGO_ENABLED=0`) |
| Конфигурация | YAML-файл (`gopkg.in/yaml.v3`), путь через `--config` |
| Матчинг | подстрока в любом месте строки, регистрозависимо, счёт по строке |
| Самосброс | отключаемый: `reset.enabled` + `reset.schedule` (стандартный 5-польный cron, дефолт `0 0 * * *` — раз в сутки в полночь) |
| Lock-файл | путь в конфиге (`lock_file`), уникальный на инстанс |
| Логирование демона | блок `logging`: level + output (`journald`/`file`) + file |
| Мультиконфиг | шаблонный юнит `logstat@<имя>` → `/etc/logstat/<имя>.yaml`, несколько логов на хост |
| Heartbeat-ключ | `logstat:heartbeat:<host>:<action>`, включается/отключается параметром `heartbeat_key` (дефолт `true`); целочисленный счётчик пишется всегда |
| Коллизия ключей | только при общем Redis + пересечении `actions`; разный Redis/db или непересекающиеся actions решают. Оговорено в доке, софтом не предотвращается |
| Удаление пакета | postrm чистит осиротевшие enable-симлинки инстансов (`.wants/logstat@*.service`) + `daemon-reload`; prerm останавливает `logstat@*` |
| Привязка к ПО | нет — произвольный построчный лог |
| systemd-зависимости | только `network-online.target`; без redis/nginx |
| Redis | возможно удалённый; буфер в памяти переживает недоступность |
| Старт без лог-файла | поддерживается (ждём появления) |
| Архитектуры | linux/amd64 + linux/arm64 |
| CI/релиз | GitHub Actions + GoReleaser (build + nfpm + release) |
| Пакеты | `.deb` и `.rpm` через nfpm |
| Дефолт `log_path` | нейтральный `/var/log/app.log` |
